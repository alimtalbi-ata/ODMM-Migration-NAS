# ODMM V228.97 — Read-only verifier directory fencing (POSIX laboratory)

Author: Abdelhalim Talbi. Scope: Linux Full / Linux Compact **local laboratory** only.

## Problem

`verify_pair` previously opened a pathname after checking only its leaf symlink status. A concurrent rename or symlink substitution of the parent directory could redirect the read to an unrelated tree; post-hash pathname identity was not checked. The old inode's contents could still be read while a different pathname was reported as verified.

## Change

`_digest` pins the immediate parent directory using `O_DIRECTORY | O_NOFOLLOW`, opens the regular file with `dir_fd` and `O_NOFOLLOW`, compares parent and leaf device/inode identity against their pathnames after hashing, and checks ctime, mtime, mode, size and inode stability on the open file descriptor. A mismatch fails closed. This is advisory, not a distributed fencing protocol.

## Tests

`python3 -m unittest discover -s 09-Tools -p 'test_linux_lab_verifier_parent_fence.py' -v`

The deterministic tests cover normal hashing, pair verification, parent replacement by a symlink during a read, leaf replacement by a symlink during a read, symlinked parent refusal, and metadata-only mutation. Tests do not write to any NAS endpoint.

## Limitations

Only the immediate parent is pinned; ancestor symlinks and a race after the final check remain possible. A remote NFS/SMB server can change content without obeying local inode assumptions. No ACL, xattr, UID/GID, SID, ADS, locking, durable remote commit, multiserver fencing or production safety is proven. SQLite `UNCERTAIN` remains manual-review-only; this change does not enable auto-resume. No Windows UI qualification or executable is included in this change.
