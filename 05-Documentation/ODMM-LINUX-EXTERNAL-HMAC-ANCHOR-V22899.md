# ODMM V228.99 — External HMAC anchors for Linux local-lab identity evidence

**Author:** Abdelhalim Talbi  
**Scope:** Linux Full / Linux Compact, isolated local POSIX lab. **NOT a production NAS qualification.**

## Problem and change

Prior identity observations used SHA-256 within the same SQLite database. A writer
with database modification access could replace both the observation and its
unkeyed digest. V228.99 adds an **optional, independently controlled** HMAC-SHA256
anchor for a previously recorded immutable identity observation.

- `odmm_linux_lab_external_anchor.create_anchor(...)` stores one canonical,
  exclusive-create, fsynced anchor file; overwrites are refused.
- `verify_anchor(..., key_resolver=...)` verifies the HMAC with a key supplied
  by an independently trusted resolver, then checks the complete current
  SQLite observation and its intent binding.
- `inspect_uncertain(..., anchor_dir=..., key_resolver=...)` includes the
  optional `external_anchor` advisory result. Missing, changed, unsafe or
  unauthenticated anchors fail closed.
- The decision remains `MANUAL_REVIEW_REQUIRED`, even with a valid anchor.
  No automatic retry, cleanup, VERIFIED promotion or cutover is added.

## Threat model and deployment contract

The anchor directory **must be outside the SQLite trust boundary** and protected
against journal-writer modification. The HMAC key must be generated by an
independent secret manager, contain at least 32 random bytes, and **never**
be stored in the repository, SQLite, logs, artifacts, or the anchor directory.
The `key_id` is a public lookup identifier, not a key.

The caller provisions a pre-existing protected directory, records the anchor
only after the identity observation is durable, and passes a resolver that
retrieves the correct external key. Anchors are immutable and created with
`O_EXCL|O_NOFOLLOW`, mode 0600, fsync(file), fsync(directory), with
descriptor-pinned ancestor checks. Verification rejects symlink paths and
non-regular anchor files.

**Key rotation:** This iteration deliberately does not replace existing
anchors or automatically migrate to a new key. Preserve retired keys in a
read-only resolver for verification until an explicit dual-signature
rotation and revocation policy is implemented. A missing/revoked key must
cause verification failure, never fallback to an unkeyed digest.

## Test and evidence boundaries

Run on Linux:

```sh
python3 -m unittest discover -s 09-Tools -p 'test_linux_lab_external_anchor.py' -v
```

CI runs the suite independently for Full and Compact. Cases cover intact
anchors, missing/wrong key, anchor tampering, SQLite tampering with a
recomputed SHA-256, symlink replacement, exclusive creation, resolver
outage, and the immutable UNCERTAIN manual-review decision.

**Not covered:** remote NAS servers, NFSv3/v4, SMB, NTFS/NFSv4 ACL,
distributed locks, crash-consistent external storage transactions, malicious
root with access to the HMAC key, compromised trusted resolver, concurrent
ABA swaps, power-failure durability across distinct devices, or real UI
screenshots. No new Windows or Linux binaries are asserted by this change.
