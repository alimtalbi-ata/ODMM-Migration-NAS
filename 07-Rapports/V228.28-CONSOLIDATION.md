ODMM V228.28 - Consolidation fonctionnelle du moteur natif
Auteur : Abdelhalim Talbi

Changement réel : factorisation de la transition transactionnelle CLAIMED vers VERIFIED_POSIX_SUBSET dans IncrementalExecutor._commit_verified_claim_locked.
Deux chemins consommateurs : execute_claimed et acknowledge_reconciled.
Les vérifications source/cible, l'exclusivité, le contrôle du token et les conditions de réconciliation restent distincts.
Aucun fallback, effacement, cutover ni reprise automatique n'est introduit.

Qualification : 40 tests du sous-système incremental réussis sous Linux, via unittest discover.
Non qualifié : NAS physiques, fidélité ACL SMB/NFS, compilation Windows, performances industrielles.
La refactorisation ne prouve pas à elle seule l'équivalence sur tous les environnements.

Architecture : moteur natif POSIX -> inventaire -> planificateur -> exécuteur -> registre SQLite.
Transaction commune : vérifier l'état CLAIMED + token -> UPDATE conditionnel -> COMMIT, sinon ROLLBACK.
Scénario illustratif (fictif) : une copie interrompue après publication est bloquée jusqu'à réconciliation explicite, puis accusé de vérification.

Prochaine étape : approfondir le contrôle des métadonnées et tester les transitions concurrentes et les reprises sur crash.
